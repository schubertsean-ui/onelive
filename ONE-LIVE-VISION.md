# One Live — Vision

Founder vision lock. Ratified: 2026-09-02. Status: in force.

This is the "why" beneath ONE-LIVE-COVERAGE-LAW.md (governs scope) and
ONE-LIVE-OPERATING-LAW.md (governs how you work). It does not change
either file's precedence. It is the check every ticket must pass:
**if a ticket shrinks this vision, the ticket is wrong.**

## The lock
- Map, not shop.
- Every category, any locale.
- No category weighting.
- Publishers trusted until wrong.
- On-device plans.
- Heartbeat = de-identified pulse.
- Beautiful + automagical.
- Trust serves the vision.

## What each line means here

**Map, not shop.** One Live is a map of what's happening, not a shop
that sells placement on it. No pay-to-rank surface, ever (CLAUDE.md
Prime directive 1; Coverage Law).

**Every category, any locale.** The catalog holds every event or
activity, everywhere it operates. No refused locale, no refused
category, no dropped single-source row (Coverage Law).

**No category weighting.** The model stays general — it does not rank
one category over another. A specific door (a view, a city) may
specialize; the underlying model never does.

**Publishers trusted until wrong.** A source starts credible. Confidence
moves down on evidence, not up from a default of suspicion. Disputed is
always shown, never hidden (4-state confidence model: unverified /
likely / confirmed / disputed — CLAUDE.md Architecture).

**On-device plans.** What a person saves and intends to do lives on
their device, not as a server-side behavior log.

**Heartbeat = de-identified pulse.** Heartbeat (STATE.md: deferred
behind Creator-Venue Matching for v1) is a de-identified, aggregate
pulse of activity — never a trace of one person's movements or
attendance.

**Beautiful + automagical.** The product is beautiful, and the
AI/automation behind it works invisibly.

**Trust serves the vision.** Gates, evidence, confidence states, the
independent evaluator — all of it exists so the map can be trusted. It
is infrastructure for the vision, not a vision of its own.

## Using this file
A ticket that narrows any line above — drops a category, adds a
paywall/login bypass, adds pay-to-rank, centralizes on-device data,
re-identifies Heartbeat, or treats a trust gate as the product instead
of a means to it — is wrong. Note it under Refused (Operating Law)
rather than build it.
