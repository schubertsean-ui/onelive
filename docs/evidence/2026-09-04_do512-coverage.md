# Reading one public desk end to end — Do512

**What you are about to see.** Do512 is one desk, and we walk its public dated
list as ONE door: page by page, following only the links that page itself
prints, turning each card into one of our rows. Three tables follow — which
pages opened, what Do512 calls its categories against what we call ours, and how
many of those happenings we already hold. Nothing here was published, promoted,
or shown to anybody. This is a measurement, not an ingest, and the catalog is
exactly as it was before.

Session Contract #63, 2026-09-04. Every command that derives a number is printed
above it, so any of them can be re-run rather than trusted.

```
$ curl -sS -o /dev/null -w '%{http_code}' -A 'OneLiveBot/0.1' "https://do512.com/events/today"

$ curl -sS "$HTTPS_PROXY/__agentproxy/status"        # the proxy's own record

  "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)",
  "host": "do512.com:443" }]
```

Our own network refused before Do512 was ever asked. The proxy's documented
instruction for a policy denial is to report it, never to retry or route around
it, so no second path was tried.

**This is our block, not the desk's.** Do512 did not refuse us — we never
reached it. The walker records that distinction instead of flattening it:

on a start URL is triage").

page of this desk, so no row may claim to have seen one. The single
`desk_id_cited` row is the `live-music` path segment that a committed pack door

Do512 states its categories in the URL PATH (`/events/live-music/today`), not in
a query parameter, which is why this session added `href_path` to
`worker/locale/kind_map.py`: with only the query-parameter signal, a map for
this desk could match nothing and every card would read as uncategorised. Two
refusals ride with it — the prefix is anchored at the path root, and a purely
numeric segment is never a category, because `/events/2026/9/12/some-show` is how
a desk addresses ONE listing.

## What the fixture run shows that a live run must not lose

* **The list continues behind a control we cannot follow.** Page 3 states a
  `Load More` button. A link-following walker sees no next link and would
  otherwise stop on `no_next_link` — which reads as an EXHAUSTED desk. It now
  stops on `next_control_not_a_link`, `exhausted` stays false, and the coverage
  table prints "on_desk is a FLOOR, not the desk's list". We still do not follow
  it: synthesising the address that script would have called is a guess about a
  stranger's routing.
* **A next link we REFUSED is our stop, not the desk's end.** The same false
  claim was already being made one step earlier: a next link pointing off the
  desk's host was declined (correctly) and then reported as `no_next_link` —
  our refusal, filed on the desk's account. It stops on
  `next_link_not_followed` now, and `exhausted` stays false there too.
* **No invented dates.** A card that prints prose where the clock should be
  (`this Saturday, late afternoon`) keeps the prose verbatim and leaves the
  instant NULL. A missing minute is not a missing night.
* **No identity required to exist.** A card with neither its own address nor a
  date is a row. Existence is the door's question, never a field test.
* **Holes fill, values never overwrite.** One card is stated twice on page 1
  (JSON-LD and HTML, disagreeing on the FORM of the date) and again on page 2.
  It is ONE row: the first reading's instant stands, and the later readings fill
  the date text and the venue it was missing.
* **An unmapped category is printed, not guessed.** `nightlife` is not one of
  our kinds; those rows land on `other` and the word is printed so the table can
  be completed from the desk's own vocabulary rather than from memory.

## What this changes, and what it does not

**It does not change what anyone sees.** This PR writes no candidate, promotes
nothing, and touches no consumer surface. `tools/desk_coverage.py` prints
tables; `worker/locale/` returns rows in memory. Following pages and reading
cards without a promote path does not change what friends see on Tonight, and
R-105 already names the three files that would hide these rows if they were
wired forward.

**What it does change** is that a desk's list is now bounded by its pages, not
by whichever page happened to be first — and that a desk whose list continues
behind script, or past a link we refused, can no longer be reported as fully
read.

## The one command that closes the live column

```
python3 tools/desk_coverage.py --door do512-today --real                  # live walk
python3 tools/desk_coverage.py --door do512-today --real --store          # ...and the gap
```

Run from anywhere egress to `do512.com` is permitted. It needs no credential and
no login: it walks the same public list a person browsing the site walks, one
page at a time, and stops at the first wall. That run prints the live page
count, the live row count, the categories Do512 actually states (including every
one this table does not yet cover), and the on_desk vs in_store gap. Until it
runs, no doc may state how many happenings Do512 lists (R-109).
