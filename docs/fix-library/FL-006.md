# FL-006 — stale ingest still walking

- Symptom: live-miss / stale-writer
- Layer: ingest / CI
- Cause: wrong-gate (ops)
- Scope: universal
- Failure: a newer ingest (the actual fix) sits pending while an older commit keeps writing.
- Why: `.github/workflows/desk-ingest.yml` concurrency group `desk-ingest` had `cancel-in-progress: false`. One writer at a time was right. Keeping the *old* writer was wrong.
- Success: the ingest on current master is the one that walks. An older run does not hold the lock.
- Fix: `cancel-in-progress: true`. Dispatching a new write cancels the stale walk. Still one writer at a time.
- Applied: cancel run 36 (2026-09-09). Set cancel-in-progress true on the workflow.
