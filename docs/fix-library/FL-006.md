# FL-006 — stale ingest holds the lock

Class: OPS / INGEST

Failure: a newer product ingest sits pending while an older commit keeps walking.
Observed: desk-ingest 36 on SHA 87866f33 (docs) blocked run 37 on 96fdfd65 (FL-005).

Cause: `.github/workflows/desk-ingest.yml` uses `concurrency: desk-ingest` with `cancel-in-progress: false`. We also dispatched ingest on docs-only merges.

Fix:
1. Newest ingest on master wins — `cancel-in-progress: true`.
2. Do not dispatch desk-ingest on docs-only commits. Dispatch when the walk can change the catalog (gate, reader, pack door).

Success: the running ingest SHA is the current product SHA. Live count is still the only Success for Ticket B.
